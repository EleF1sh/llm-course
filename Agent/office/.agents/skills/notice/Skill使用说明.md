# 通知写作助手 V1.1｜使用说明

## 一、Skill 概述

**名称：** tongzhi-writer-v1.1-docx

**文种：** 通知

**完整工作流：** 生成初稿 → 事实复核 → 自动修订 → Markdown 输出 → DOCX 套版

**版本：** V1.1.0 (Pre-release)

---

## 二、触发方式

在 WorkBuddy 中输入以下任一指令即可触发本 Skill：

- "帮我写一份通知"
- "起草通知"
- "根据这些材料整理通知"
- "修改通知"
- "生成通知文稿"

---

## 三、支持的工作模式

### 模式 1：通知初稿生成

输入原始材料，Skill 自动调用通知生成提示词，输出 Markdown 通知初稿。

**输入要求：**
- 主要任务说明
- 原始材料
- 可选：主送对象、发文单位、成文日期、特殊要求

**输出：** Markdown 通知初稿（draft_v1）

### 模式 2：事实一致性复核

将原始材料和通知稿进行逐句对照复核。

**复核内容：**
- 材料外新增
- 关键材料遗漏
- 时间状态错误
- 数据和日期问题
- 主体新增或错置
- 文种与结构问题
- 用户任务执行问题
- 生成稿内部矛盾

**输出：** 复核报告（review_result）

### 模式 3：自动修订

根据复核结果和原始材料自动修订通知稿。

**修订原则：**
- 原始材料是最高事实依据
- 只做最小必要修改
- 不得新增材料外事实
- 不得擅自扩大通知对象、工作要求或责任范围

### 模式 4：Markdown 输出

生成结构清晰、可继续进入 DOCX 套版的 Markdown 文件。

**默认文件名：** `通知_最终稿.md`

### 模式 5：DOCX 生成

将最终 Markdown 通知稿套入通知 DOCX 模板。

**默认文件名：** `通知_最终稿.docx`

### 模式 6：完整流程

一次性执行完整流程：

```text
生成 → 统一复核 V1.1 → 自动修订 → Markdown → DOCX
```

---

## 四、材料不足时的处理

当材料不足以明确通知事项时，Skill 会要求补充信息，不会自行编造。

**必须明确的核心信息：**
- 通知对象（发给谁）
- 通知什么事
- 核心事项（如会议时间地点、工作要求、活动安排等）

**使用占位符的情况：**
- 主送对象未确定：使用 `〔主送机关〕`
- 成文日期未确定：使用 `〔日期〕`
- 发文单位必须使用材料中的完整名称，不得自行简称

## 六、DOCX 排版支持的要素

通知DOCX由 `scripts/notice_document_factory.py` 在运行时创建，不依赖二进制模板。支持以下排版要素：

- 通知标题（单行/多行、短标题/长标题）
- 主送对象
- 正文自然段
- 分层序号（一、/（一）/1.）
- 落款单位
- 成文日期
- 附件说明

---

## 七、使用注意事项

1. 本 Skill 只处理"通知"文种，不处理请示、报告、函、纪要等
2. AI 生成稿只能作为可审核初稿，不能替代人工核实和审批
3. 涉及敏感信息时请先脱敏
4. 未经确认的模型建议不得直接写入正式公文
5. 最终格式以本单位正式模板和 OA 系统为准
6. 不得在通知中出现"妥否，请批示""以上请示"等请示专用语言

## 九、与请示 Skill 的关系

- `tongzhi-writer-v1.1-docx` 和 `qingshi-writer-v2.1-docx` 是独立的两个 Skill
- 共用相同的样式体系和 DOCX 操作方法
- 提示词和模板各自独立，互不影响
- 修改通知 Skill 不会影响请示 Skill 的行为
